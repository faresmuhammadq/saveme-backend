**Overall Status**: ✅ PASSED (33 passed, 0 failed)

The feature is a JSON API with no UI, so the acceptance scenarios were run end to end over HTTP rather than in Playwright. The scenarios cover every acceptance scenario of US1 to US6 in spec.md, 33 in all, with 83 assertions. The script used Python `requests` (curl-equivalent) against http://saveme-backend.test/api/v1, with the headers `X-Client-Platform: android` and `X-Client-Version: 1.0.0`.

**Setup**
- Fresh people were seeded through `UserFactory` and `ProfileFactory` and signed in through `POST /auth/login`:
  - A: verified, Africa/Cairo;
  - B: verified partner;
  - U: unverified;
  - N: verified, America/New_York;
  - X: verified, with no profile.
- Wallets named `QA015 E2E …`, categories, transactions, a recurring rule and budgets were created over the API.
- B's shared-wallet memberships were inserted under the wallet scope counter. Leaving and rejoining (US3-3) were done the same way.

**Server side**
- US6-4: one budget tombstone was aged 91 days in the database, then `dev sync:purge-tombstones` ran for real. Before the run, no other tombstone older than 90 days existed in the dev database.
- Start-day changes went through `PUT /me/profile`. The clock was not moved.

**Clean-up**: all E2E data was deleted afterwards, together with the QA data.

**Evidence**: every request and response is under `test-reports/http/<story>-s<n>.txt`. Credentials are redacted.
