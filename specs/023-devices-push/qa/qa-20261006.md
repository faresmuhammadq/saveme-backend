## Notes

- The `log` gateway records through the application log (`push_logged`) and the `push_notifications` ledger (`state`, `skip_reason`); both were used as assertions.
- A default queue worker does not process the `notifications` queue; this QA ran `queue:work --queue=notifications,default`. Deployment note: workers must listen to `notifications`.
- Operational slip during QA: an `UPDATE users SET email_verified_at` without a where on the dev DB marked other unverified dev accounts verified (throwaway data only).
- Back-office screen check: counts-only, covered by `NotificationFiguresTest`; no visual run.
