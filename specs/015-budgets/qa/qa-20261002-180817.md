# QA Report: Budgets (spec 015, B8)

**QA Mode**: CLI QA. HTTP was driven by Python `requests` (curl-equivalent) against the running dev app. Server-side setup (people, shared-wallet memberships, leaving a wallet) was done with a PHP script run in the `dev` container.
**Date**: 2026-10-02
**Feature**: [spec.md](../spec.md)
**Environment**: Fedora Linux 44 (kernel 7.2.7) host; `dev` container with PHP 8.5 and PostgreSQL 16; http://saveme-backend.test/api/v1
**Verdict**: ✅ ALL PASSED. No product defect was found. Every failure on the first runs came from the test script itself (see Failure Details).

## QA Summary

**Setup**
- Ran `dev queue:restart`. The three `2026_10_06` migrations were already applied. The dev database was not reset, seeded or put into maintenance mode, and other agents could use the app during the run.
- QA people were seeded through `UserFactory` and `ProfileFactory` (`qa015-{a,b,u,n,x}-<run>@example.test`). Each signed in through `POST /auth/login`:
  - A: verified, Africa/Cairo, the main owner;
  - B: verified, Africa/Cairo, the partner (an editor in A's shared wallets);
  - U: unverified;
  - N: verified, America/New_York;
  - X: verified, **no profile row**.
- Wallets, categories, transactions, recurring rules and budgets were created over the API. Shared-wallet memberships were inserted under the wallet scope counter, as in earlier QA runs. "Leaving" a wallet was simulated by tombstoning the `wallet_members` row under the wallet counter.

**Time**
- "Today" was 2026-10-02 in both Cairo and New York, so the current Budget Period with start day 1 was 2026-10-01 to 2026-10-31.
- Changes to the start day were made through `PUT /me/profile` for real. No clock was moved.

**Result**
- 238 HTTP checks in 22 scripted test-case groups (TC-000 to TC-021), plus 24 exploratory probes (TC-030). Every check passes in its final form.
- The probes covered concurrent identical creates (1×201 + 3×200, version 1, three runs), concurrent PATCH (1×200 + 3×409), stale delete and archive, server-owned and unknown members, a credit-card wallet in KWD, projection overflow (null), and a future-dated expense inside the current period.
- No product defect was found, and nothing in `budgets.yaml` or `sync.yaml` changed.

**Clean-up**: all QA and E2E people, wallets, categories, transactions, rules, occurrences, budgets, start-day history rows, sessions and keys were deleted afterwards (`storage/app/private/qa015/cleanup.php`, not committed). The totals were 30 people, 31 wallets, 61 transactions and 68 budgets. Audit entries stay, because the table is append-only by design.

## Failure Details

No product failure.

### Test-side corrections (no product defect)

- TC-013 (first run): the script read the next cursor at `meta.page.next_cursor`, but collections carry it at `meta.next_cursor`. The script was fixed.
- TC-016: the script expected the whole user feed in `change_seq` order. `wallet_member` rows are stamped by wallet counters (spec 013), so the check was narrowed to user-scope rows.
- TC-017: the first batch mixed an `archive` op and a `wallet_id` into one envelope, so the whole envelope was refused with 422. That is the frozen envelope rule (spec 013). Both cases now run as separate batches and assert the envelope refusal.
- TC-020: the occurrence's member is `recurring_rule_id`, not `rule_id`.
- TC-021: the 415 probe first sent no body. With a `text/plain` body it gives 415.
